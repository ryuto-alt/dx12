# GI 基盤 設計書（山 1: 空の遮蔽つき GI を既定の環境光にする）

- 作成: 2026-10-01 / 親（設計・統合・最終レビュー）。実装は段階ごとにサブエージェント。
- 前提の診断: ギャップ診断レポート（小窓の部屋で「既定 / 既存機能全 ON / パストレーサー」を比較）。
- 基準: RTX 5060・1080p・60fps。正解 = エンジン内パストレーサー（`dx12_render_reference`）。
- ヒアリングで確定: 既存シーンの見た目は変えない（**新規シーンだけ新しい既定**。移行は明示操作）/ 重視 = 屋内ホラー + キャラ / 判定シーン = 検証用の部屋 + MikuOblivion のコピー（元は読み取りのみ）。

## 0. 何が起きているか（実測で確認した事実）

| # | 事実 | 根拠 |

## 1. 目標と合否

**目標**: 新規シーンでは何も設定しなくても、屋内が「窓と灯りの量に見合った明るさ」になり、色の照り返しが出て、金属が室内で空を映さない。

| ID | 合否基準（数値） | 測り方 |
|---|---|---|
| A1 | 検証用の部屋（GR-1）で、壁・天井・床の領域ごとの平均輝度がパストレーサーと **±0.5EV 以内**（現状: 推定 +2EV 以上明るい） | 線形 PFM 同士、領域マスク。§3 |
| A2 | `ddgi_leak` 相当の薄壁シーン（GR-3）で暗い側の黒潰れ率が PT 比で ±10pt 以内、平均輝度 +0.5EV 以内 | 同上 |
| A3 | 赤い敷物の照り返し: GR-1 の天井の R/G 比が PT と同じ向き（R>G）で、比の差 20% 以内 | 同上 |
| A4 | 金属球の環境反射が空より暗い（GR-1 のクロム球領域の平均輝度が既定比 −1EV 以上） | 同上 |
| A5 | 既定 OFF（既存シーン）は決定論スクショで **差分 0**（golden 4 枚 + 既存の ctest） | `tools/bench/golden.mjs`、ctest |

## 2. 段階

依存: `S0a ∥ S0b ∥ S1` → `S2` → `S3` → `S4` ∥ `S5` → `S6`（親）。

### S0a 球の G-Buffer 法線の反転（RT-AO 黒化）
- 深度+速度+G-Buffer プリパスの VS / PS（`shaders/shadow/DepthPrepass*`・`ForwardInstanced` 系・`ScreenSpaceCommon.hlsli` の `SS_EncodeGBuffer`）で、球プリミティブ（インスタンス描画される単一サブメッシュ）の法線が反転する経路を特定して直す。仮説: インスタンス経路の法線変換 or プリミティブのメッシュ法線の向き。**仮説は検証してから直す**。
- 合否: A7。他の形（box / plane / glTF / スキンド / 地形）の G-Buffer 法線も同じ確認を表にして報告する。

### S0b レイのヒットでマテリアルの色と自己発光を読む
- DDGI のヒットシェーディング（`RtHitAlbedo`）が、ラスタと同じ **baseColor テクスチャ × tint（packedTint の rgb）× 頂点色** と **emissive（色 × 強度、emissive テクスチャ）** を返すようにする。
- パストレーサー（`src/renderer/PathTracer.cpp` / `shaders/pt/`）は既に材質表を持つので、**その表を DDGI / RT 系と共有する**のが第一候補（ヒットの見え方が PT と一致する）。`GeometryInfo`（16 B）を太らせる場合は RT 影・RT-AO・`rtAlbedo` デバッグへの影響を確認する。
- 合否: `render_debug rtAlbedo` で GR-1 の敷物が赤・壁が灰になる / `dx12_get_dxr stats` に材質付きの件数が出る / RT 影・RT-AO の絵は不変。

### S1 GI 評価ハーネス（以後の全段階の物差し）
- 検証シーンを `tools/parity/scenes/gi/` に scene_spec 形式で置く（公開リポジトリに入れてよい自作の箱だけ）:
  - **GR-1** 小窓の部屋（8.4×3.2×6.4m・西に 2×1.4m の窓・太陽 方位 270°/高度 33°・赤い敷物・金/クロム/白/青の球）。診断で使ったもの。
  - **GR-2** 窓の無い部屋 + 天井の点光源 1 灯（空の寄与が 0 であるべき場所）。
  - **GR-3** 薄い仕切り壁（厚さ 0.1m）を挟んだ明暗 2 部屋（`ddgi_leak` 相当）。
  - **GR-4** 暗い廊下 + 自己発光の看板 + 赤い電球 3 灯（ホラーの典型）。
- 撮影: 同じカメラで ①ラスタの線形 PFM（`dx12_screenshot_final {format:"pfm", deterministic:true}`）②PT の PFM（`dx12_render_reference`、1024spp・8 バウンス）。比較を公平にするため両方とも **定数 ambient = 0**、ポスト前の線形で比べる。
- 指標: 領域マスクごとの平均 log2 輝度差（EV）、黒潰れ率、R/G 比、HDR-FLIP（`tools/parity` の既存実装を使う）。出力は JSON + 並べ画像（ラスタ｜PT｜差分ヒートマップ）。
- 1 コマンドで全シーンを回せること（`tools/parity/gi_eval.ps1` 等）。エンジンは fleet（`dx12_engine_launch`）か `engine_instance.ps1` の背景起動。
- 合否: 現状のベースライン数値（GI OFF / DDGI 現行 ON）が出て、A1〜A4 の判定が機械的に出る。

### S2 DDGI の光輸送を正しくする（本丸）
1. **プローブ分類**: レイの裏面ヒット率が閾値（RTXGI 既定 25%）を超えるプローブは「壁の中」として無効。無効プローブは補間の重み 0。
2. **プローブ再配置**: プローブごとのオフセット（バッファ。格子間隔の 45% まで）を持ち、裏面ヒットが多い向きの反対へ / 最も近い面から離す方向へ毎フレーム少しずつ動かす。格子が変わったらリセット。
3. **空の項の置き換え**: ヒット面の照明 = `albedo × (直接光 + 前フレームのプローブ irradiance(ヒット点))`。空はミスしたレイからだけ入る。F2 の失敗は 1・2 と補間重みの見直しで潰す（**順番を守る: 1・2 を入れて GR-3 の漏れが PT 並みになったのを数値で確認してから 3**）。
4. 補間: RTXGI と同じ surface bias（法線 + 視線方向）・wrap 重み・Chebyshev。`wrap*wrap+0.2` の 0.2 の扱いを RTXGI と突き合わせる。
5. **空の可視率**: irradiance アトラスの `.a`（今は常に 1.0）に「その方向の半球で空が見えている割合（コサイン重み）」を書く。S3 の鏡面遮蔽が読む。
6. 多重バウンスは既定 ON（`bounceIntensity` は 1 に近い値。アルベドの 0.9 クランプは維持）。
- 合否: A1・A2・A3。既定 OFF で差分 0（A5）。

### S3 フォワードへの統合（既定の環境光にする）
- DDGI の範囲内では拡散の環境光を DDGI が**置き換える**（IBL / 定数 ambient を使わない）。範囲外は従来どおり。
- **鏡面遮蔽**: 空の prefiltered 反射に S2-5 の空可視率を掛ける。遮られた分は DDGI の irradiance で粗い反射を近似（ラフネスで重み）。正式な室内反射は山 2（反射プローブ）。
- **SSGI のミスを DDGI へ**: SSGI のレイが外れたら IBL ではなく、その画素の DDGI irradiance を使う（DDGI が無いときだけ IBL）。
- 自己発光面は S0b により DDGI へ光を出す（GR-4 の看板が周りを照らす）。
- 物理単位（`lightingUnits:1`）でも同じ式が正しいこと（単位の換算を確認）。
- 合否: A1〜A4 を S3 込みで再判定。A4 はここで初めて合格する想定。

### S4 自動ボリュームと性能
- **カメラ追従のスクロール格子**（RTXGI の infinite scrolling と同じ。格子をずらすときは端の列だけ履歴を捨て、残りは保持）。**2 カスケード**（近: 1m 間隔 / 遠: 4m 間隔、各 16×8×16 程度）。手置きのボリュームは従来どおり使える（シーンに置いたら優先）。
- ヒット点の点光源: 全灯の総当たりをやめ、**ワールド空間の粗いライトグリッド**（または範囲内上位 N 灯）で絞る（F8）。
- 更新の間引き: 1 フレームに更新するプローブ数の上限（予算 ms から決める）。
- 合否: A6。Dead Mall コピー（455 灯）でも 1.5ms 以内。

### S5 新規シーンの既定と移行
- 新規シーン（テンプレート・`dx12_new_scene`・ランチャーの新規作成）は「GI モード = 新」: DDGI 自動ボリューム ON・定数 ambient 0・SSGI は DDGI フォールバック付きで ON・RT 影 ON（DXR 非対応 GPU では自動で従来へ）。
- 既存シーンは JSON に GI モードが無い = 旧として読み、見た目は 1px も変えない（A5）。
- 移行: インスペクタの「シーン設定」に「新しい GI に切り替える」ボタン + MCP（例 `dx12_set_gi_mode {mode:"new"|"legacy"}`）。Undo 可能。
- Lua に出す場合は Lua API チェックリスト（MCP 辞書 + リファレンス 3 点 + 予測変換）まで。
- 合否: 新規シーンを作って何も触らず GR-1 相当を置くと A1 を満たす / 既存の golden 差分 0。
